# Развёртывание

Два независимых таргета. Фронт работает без бэкенда, бэкенд не нужен для демо.

## Статичный фронт на GitHub Pages

Сборка в workflow `github-pages`, job `build`. Переменные:

| Переменная | Значение | Эффект |
|---|---|---|
| `GITHUB_PAGES` | `1` | `output: "export"`, вместо `standalone` |
| `NEXT_PUBLIC_BASE_PATH` | `/frame-atelier` | префикс для ассетов и роутов |
| `NEXT_PUBLIC_API_URL` | не задана | все расчёты идут в браузере |

Локально та же сборка:

```bash
cd web
MSYS_NO_PATHCONV=1 GITHUB_PAGES=1 NEXT_PUBLIC_BASE_PATH=/frame-atelier npm run build
```

Под `MSYS_NO_PATHCONV=1` в Git Bash, иначе слэш в basePath превращается в windows-путь и сборка падает.

## Go API одним образом с фронтом

`docker build -t frame .` поднимает один контейнер: Go API на `:9000`, Next standalone на `:3000`, Caddy на `:8080`. Caddy роутит `/v1/*` и `/healthz` на API, остальное на фронт.

В этом образе `NEXT_PUBLIC_API_URL=origin`, то есть браузер зовёт тот же origin через прокси. Без `origin` в значении переменная считается незаданной и фронт молча уходит на локальную математику, а API в контейнере остаётся ненужным. Это был реальный баг, пока `origin` не появился как отдельный режим.

```bash
docker build -t frame .
docker run --rm -p 8080:8080 frame
curl -s localhost:8080/healthz
```

`fly.toml` описывает тот же образ: `primary_region = "fra"`, `internal_port = 8080`, 1 GB RAM, автостоп. `fly deploy` поднимает его как есть.

## Три режима API

| `NEXT_PUBLIC_API_URL` | Что делает фронт | Где используется |
|---|---|---|
| не задана | считает мерки и салоны в браузере | GitHub Pages |
| `origin` | зовёт `/v1/...` на том же origin | единый Docker-образ |
| абсолютный URL | зовёт указанный хост | локальная разработка с `go run` |

Режимы покрыты тестами в `web/src/lib/api.test.ts`, включая проверку, что `origin` действительно уходит в `/v1/fit`, а не в локальный расчёт.

## Что пока не развёрнуто

Хранилища нет. Таблицы из раздела 11 ТЗ, согласие на исследование и стилист появятся вместе с фазой 3, и тогда же понадобится том или база для образа, который сейчас полностью stateless.

Ключ провайдера для стилиста задаётся переменной окружения на стороне API и никогда не попадает во фронт: `NEXT_PUBLIC_*` инлайнится в бандл и читается из публичного JS.

## Проверка перед деплоем

Job `verify` гоняет lint, типы, тесты фронта, статичную сборку и тесты Go, включая parity-тест на общем фикстуре `testdata/fit-parity.json`. `build` и `deploy` зависят от него и не стартуют на pull request.
